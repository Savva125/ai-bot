# AI-помощник с доступом по ключу

Windows-приложение читает выбранное окно и контролирует ввод/отправку на устройстве
пользователя. AI работает на вашем GPU-хосте. Сервер проверяет срок, устройства
и лимиты. Вы создаёте ключи через личный Telegram-бот и выдаёте их вручную.
Сайт и платёжный провайдер не нужны.

## Клиент

Из исходников: Python 3.12, `python -m pip install ".[desktop]"`, затем `run-client.cmd`.

1. Введите HTTPS-адрес API и ключ от администратора, нажмите «Активировать».
2. Нажмите «Начать работу» и выберите окно с открытым диалогом.
3. «Остановить» отменяет дальнейший ввод и отправку, включая поздний ответ сервера.

Срок начинается при первой активации. Ключ и токен хранятся в системном хранилище
Windows, отдельно для адреса сервера. В JSON сохраняется только публичный адрес.
**Ctrl+Shift+L** — смена ключа; **Ctrl+,** — стиль, примеры и память.
Открытие этих настроек останавливает работу.

Новая история — `%LOCALAPPDATA%\CreatorDesk\history.db`. Существующая
`screen-history.db` в корне исходного проекта сохраняется и используется:
перед принятием прежней неверсионированной схемы проверяется её совместимость
и создаётся `*.before-hosted.bak`. Неизвестная схема автоматически не изменяется.
Явный выбор базы: `python -m creator_desk --client-db ПУТЬ`.

Нужная для ответа переписка, стиль и память передаются вашему серверу.
История и персонализация остаются локальными и между устройствами не синхронизируются.
Фото, видео и аудио не анализируются: читается доступный текст Windows UI Automation.

## Сборка для пользователей

```powershell
.venv\Scripts\python.exe -m pip install ".[desktop,build]"
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-client.ps1 -ServerUrl https://ai.example.com
```

Результат: `dist\CreatorDesk\CreatorDesk.exe`. Передавайте всю папку CreatorDesk
или её ZIP, включая `_internal`. Python, Node.js, CUDA и модель пользователю
не требуются. Без `-ServerUrl` адрес вводится при первом запуске.
Подписанный установщик и сертификат издателя в эту сборку не входят.

## Сервер и бот

Инструкция: [docs/HOSTING.md](docs/HOSTING.md).
Конфигурация: `deploy/compose.yaml`, `deploy/.env.example`.

```text
/new 30 500 1 Иван
/list 1
/info ID
/extend ID 30
/block ID
/unblock ID
/reset ID
```

В примере `/new` создаёт ключ на 30 дней, 500 генераций в сутки и одну установку.
Лимит обновляется в 00:00 UTC / 03:00 МСК. Серверное распознавание
неструктурированного окна также расходует запрос; Telegram обычно читается без него. `/reset` отзывает сеансы и освобождает
привязки, сохраняя ключ. При утечке ключа заблокируйте его и создайте новый.
Привязка идентифицирует установку, а не гарантирует аппаратную защиту от копирования.

Бот принимает команды только от Telegram ID из списка администраторов, в личном
чате. Ключ показывается один раз; в БД сохраняются хеши ключей и токенов.
Старые накопленные Telegram-обновления при запуске бота отбрасываются.

## Проверка

Результаты текущей версии: [docs/HOSTED_VERIFICATION.md](docs/HOSTED_VERIFICATION.md).

```powershell
.venv\Scripts\python.exe -m pip install ".[desktop,server,test]"
.venv\Scripts\python.exe -m pytest -q
.venv\Scripts\python.exe -m creator_desk --demo --demo-db .tmp\smoke.db --smoke-test
```

Тесты используют подмены модели и Telegram и не отправляют сообщения реальным
собеседникам. PostgreSQL проверяется отдельно через `CREATOR_DESK_TEST_DATABASE_URL`
для выделенной тестовой базы.

Локальный AI-провайдер и старые скрипты удалены; интеграция Node/DSH
больше не используется.
Веса для сервера сохранены в `models/model.gguf`, старая demo-база — в
`backups/legacy/demo.db`. Основная `screen-history.db` и персонализация сохранены.
Результат очистки и оставшиеся каталоги: [docs/CLEANUP.md](docs/CLEANUP.md).
